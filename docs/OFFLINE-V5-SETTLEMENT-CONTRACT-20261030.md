# TL3 V5 오프라인 재생·정산 구현 계약 (2026-10-30)

현재 플레이어 1.1.3은 온라인 인증 재생만 지원한다. 1.1.0에서 보이는 3,600 TL과 '충전' 버튼은 기존 로컬 시제품 표현으로서 실제 서버 지급·파일 충전을 뜻하지 않는다. 오프라인 재생이 완성됐다고 표시하면 안 된다.

## 고정 경제 정책
- 실제 청취 1초 = 1 TL. 일시정지·버퍼링·미청취·곡 종료 후 시간은 차감하지 않는다.
- **서버가 사전 발급하고 예약한 오프라인 청취 허용량** 안에서 파일 귀속 TL을 먼저 소비하고 부족분만 사용자 보유 TL 예약액에서 사용한다.
- 파일에 표시된 잔액 또는 PC의 캐시만으로 TL을 새로 만들 수 없다. 3,600 TL 자동 충전, 재생 시작 때 시간 묶음 선차감 금지.
- TIME FREE 이용권은 별도 청취시간 원장·상품 계약에 따라 처리하며 TL과 혼합하지 않는다.
- 오프라인에서 기록한 청취는 보상 확정이 아니다. 온라인 복귀 후 서버 검증·멱등 정산이 끝나야 권리자 및 기여도에 반영한다.

## 필수 서버/클라이언트 작업 (미구현)
1. 온라인 시 사용자·디바이스·컨테이너 SHA256·유효기간·파일 전용 TL 예약량·개인 TL 예약량을 결속한 **서명된 오프라인 권한** 발급. 서버 원장에 잠금/예약 처리하여 다른 기기 온라인 사용과 이중 차감 방지.
2. 오프라인용 기간 제한 콘텐츠 키를 플랫폼 키 관리 시스템에서 승인된 기기에만 안전하게 전달. 기존 TL3_MASTER_SECRET/KEYRING을 교체하거나 클라이언트에 노출하지 않음. 기존 V5 컨테이너 수정 금지.
3. 변조·재생 공격에 강한 로컬 내구성 영수증 장부: 연속 시퀀스, 기기/권한/콘텐츠 연결, 실제 청취 시간, 중단 복구, 단조 카운터 및 서명/검증 보호. 단순 JS 파일 기록만으로는 신뢰 불가.
4. 재접속 시 원장 API가 영수증을 **멱등** 수신하고 사전 예약분과 대사. 서명·해시·시퀀스·기간·권한 검증, 중복·역순·초과 소비 거부. 합당한 미사용 예약액 해제와 분쟁 복구.
5. 클라이언트는 서버 확인 전 '정산 대기', 성공 시 '정산 완료', 실패 시 '검토 필요'를 명시. 정산이 끝날 때까지 권리자 70:30 배분을 중복 기록하지 않는다.
6. 실제 Windows/macOS/Linux E2E: 다운로드→온라인 권한 취득→연결 차단→파일 재생→일시정지→파일 TL 먼저 소비→잔액 부족 차단→재접속→서버 대사→중복 제출 및 계정 변경 차단.

`src/offline-accounting-contract.js`는 위 정책을 위한 **순수 배분·영수증 순서 검사**로서 실제 권한, 암호화 파일 재생, 청취 원장 저장 또는 지급을 수행하지 않는다. 이 모듈만으로 오프라인 재생을 켜서는 안 된다.
